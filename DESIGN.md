# AI Builder Evaluator — Design System

**Status:** Design locked. Implementation follows.
**Principle:** One idea per screen. The interface should read like an audit document, not a dashboard. Restraint = credibility.

---

## 1. Design language

Dark, institutional, typographic. No gradients, no glassmorphism, no decorative icons. Hierarchy comes from type scale and spacing, not boxes-in-boxes. Every number on screen (score, cost, latency) is evidence — render it in mono.

Three rules:

1. **Flat surfaces, 1px borders.** Depth via border contrast, never shadows.
2. **One accent, used only for state.** Accent marks "running / attention," never decoration.
3. **Verdict-free visual grammar.** No green-check / red-X moral coloring on candidates. Status colors apply to *facts* (URL live, link verified), never to *people*.

## 2. Tokens (Tailwind config)

### Color

| Token | Value | Use |
|---|---|---|
| `bg` | `#0B0D10` | App background |
| `surface` | `#12151A` | Cards, panels |
| `surface-2` | `#1A1E25` | Nested panels, table headers, code |
| `border` | `#262B33` | All 1px borders |
| `border-strong` | `#3A414C` | Focus/hover borders |
| `text` | `#E8EAED` | Primary text |
| `text-2` | `#9AA3AF` | Secondary, labels |
| `text-3` | `#5C6570` | Tertiary, timestamps, footers |
| `accent` | `#5B8DEF` | Running state, links, focus ring, primary button |
| `ok` | `#3FB68B` | Factual pass (URL live, link verified) |
| `warn` | `#E0A93E` | Divergence flags, low confidence, fixture badges |
| `err` | `#E2606B` | Failed check, run error |
| `ai` | `#A78BDA` | **AI-authored content only** — AI Request panel, agent narrative borders |

The `ai` violet is reserved: any text generated by an LLM sits near it; anything deterministic does not. Provenance is legible at a glance.

### Type

| Role | Stack | Scale |
|---|---|---|
| UI / prose | Inter (system-ui fallback) | 13 / 14 / 16 / 20 / 28px; weights 400, 500, 600 |
| Data / evidence | JetBrains Mono (ui-monospace fallback) | 12 / 13px; scores, costs, tokens, hashes, model ID, citations |
| Labels | Inter 11px, 500, uppercase, `tracking-wider`, `text-2` | Section headers, badges |

### Spacing & shape

- 4px grid; component padding 16/24; section gaps 32/48.
- Radius: `4px` everywhere (`2px` badges). Nothing pill-shaped except status dots.
- Max content width `1100px`, centered. Single column with side rail on run view only.
- Motion: 150ms ease-out on state changes only. Running state = pulsing 1px accent border, no spinners-as-decoration.

## 3. Components

**Badge** — 2px radius, 11px caps, tinted bg at 12% opacity + colored text. Variants: `SYNTHETIC` (warn), `LIVE` (ok), `BLIND-SCORED` (accent), `FIXTURE` (warn), `DIVERGENT` (warn), `AI` (ai).

**Status dot** — 8px circle: `text-3` pending · `accent` pulsing running · `ok` complete · `err` failed.

**Agent card** — surface, 1px border; header row: status dot, agent name (14/600), confidence chip right-aligned; body: one-line summary (`text-2`); footer (mono 12, `text-3`): duration · tokens · `$0.0000`. Running = accent border pulse.

**Score block** — dimension name (14/500), JD anchor quote underneath (13 `text-2` italic), score as `4 / 5` in mono 20, confidence chip, citation in a `surface-2` blockquote with 2px `ai` left border (it's LLM-selected text). Divergent: warn badge + both scores shown side by side, struck nothing.

**Confidence chip** — outlined, mono 12: `HIGH` (ok text), `MED` (warn), `LOW` (err). Outline only — confidence is metadata, not verdict.

**Audit table** — full-width, `surface-2` header row, mono 12 cells, right-aligned numerics, hover row highlight. Columns: ts · stage · kind · model · tokens · cost · digest (truncated, click-to-copy).

**Governance banner** — single 40px strip under the page header, `surface`, border-bottom: `MODEL claude-opus-4-8 · BLIND-SCORED · ~$0.60/RUN · RECOMMENDS, NEVER DECIDES` in mono 12 `text-2`. Present on every screen.

**Buttons** — Primary: accent bg, white text, 4px radius. Secondary: transparent, 1px border. Destructive: none exists (nothing to destroy). One primary action per screen.

**Tabs** — text-only, 14/500, active = `text` + 2px accent underline; inactive `text-2`.

## 4. The AI Request panel

The centerpiece of the scorecard screen. This is where the system **briefs the reviewer and formally requests a human decision** — the "recommend-never-decide" stance made visible.

Placement: top of the Scorecard tab, full width, before the four score blocks.

```
┌─────────────────────────────────────────────────────────────┐
│ ▌ AI REQUEST · REVIEWER DECISION REQUIRED          [AI]      │ ← 11px caps label,
│                                                              │   3px `ai` left border
│  Connor Brewer (scored blind as CAND-3F2A) — complete.       │
│                                                              │
│  WHAT THE SYSTEM FOUND          (Synthesizer narrative,      │
│  3–5 sentence brief: strongest evidence w/ inline            │
│  citations, weakest area, overall confidence + why.)         │
│                                                              │
│  WHAT WAS VERIFIED              WHAT WAS NOT CHECKED         │
│  · 3/3 URLs live (mono)         · References                 │
│  · GitHub: 47 commits, README   · Education claims           │
│  · Identity links: consistent   · Anything behind login      │
│                                                              │
│  CONFIDENCE  MED   ·   DIVERGENCE  1 flag (ambiguity)        │
│  ──────────────────────────────────────────────────────────  │
│  YOUR DECISION (required — the system has none)              │
│  ( ) Advance   ( ) Hold   ( ) Decline                        │
│  [ Rationale — required, min 1 sentence …            ]       │
│                  [ Record decision ]  one per run, immutable │
└─────────────────────────────────────────────────────────────┘
```

Rules:

- Panel border-left is 3px `ai` violet; everything AI-authored inside carries the `[AI]` badge. The decision sub-section at the bottom flips to a plain `border` and `accent` button — visually exiting AI territory and entering human territory. The seam between the two zones *is* the design argument.
- "Record decision" disabled until rationale entered. Decision + rationale → `PATCH /api/runs/[id]`, one per run, immutable once written; rendered back read-only afterward.
- The brief never contains hire/no-hire language (schema-enforced upstream); the panel header says so: micro-footnote "This system produces evidence, not verdicts."
- The candidate's name is visible (blinding is model-facing, not reviewer-facing); the header pairs it with the blind token — "scored blind as CAND-3F2A" — so the panel itself states that the scorer never saw the name. Proof lives one tab over ("View packet as the Assessor saw it").

## 5. Screens

**1. Roster `/`** — Page title + governance banner. Primary action top-right: `Upload resume` (the app's front door — accent button, file input, PDF only; on success the new candidate row appears in the queue with a brief accent pulse). Candidate cards in a single column list (not a grid — it's a queue, not a catalog): name, `LIVE`/`SYNTHETIC` badge, source (`RESUME`/`SEED` in mono 12 `text-3`), evidence count, last-run cost if any, `Run evaluation` secondary button. Footer link: "View rubric" (renders `rubric.ts` verbatim — same instrument for everyone).

**2. Run view `/runs/[id]`** — Pipeline as a vertical list of agent cards in stage order (Blind → Verifiers in a 2-up row → Assessor ×2 → Synthesizer), each animating pending → running → complete off the NDJSON stream. Right rail (sticky, mono): elapsed time, cumulative cost ticking, live audit feed (last 5 entries). On `run_complete`, the pipeline collapses to a summary strip and tabs fade in. On `run_error`: `err` banner + the partial audit table — failure is auditable, the screen says exactly that.

**3. Scorecard (tabs on same page)** —
- *Scorecard*: AI Request panel → four score blocks → divergence callouts inline.
- *Agent outputs*: per-agent collapsible JSON viewers (`surface-2`, mono) + "View packet as the Assessor saw it" — renders the BlindedEvidencePacket with redacted tokens highlighted in `ai` tint.
- *Audit log*: audit table + cost roll-up row (mono, bold).
- *Transparency*: candidate-facing summary in plain prose, 16px, max 65ch — deliberately the most readable screen in the app.

## 6. Deliberate design cuts

| Cut | Why |
|---|---|
| Light mode | One theme, zero toggle code; dark suits the audit-room tone |
| Charts/graphs of scores | A 4-row score list is honest; radar charts imply false precision |
| Avatars/photos anywhere | Not an HRIS — input is a resume, and the typographic register doesn't want portraits. Names render as text like everything else |
| Animations beyond state pulse | Motion budget spent only where state changes |
| Component library (shadcn etc.) | ~10 bespoke components in Tailwind is faster and lighter for this scope |
